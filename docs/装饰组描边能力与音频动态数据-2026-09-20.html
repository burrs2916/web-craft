1. 装饰组 20 个原生形状：新增「描边细节」能力（端点 / 转折）

1.1 问题：最常被设计师调的描边细节，被硬编码进了几何

改造前 editor/data/decorationShape.ts 的几何里散落着 10 处硬编码描边细节： 

triangle / polygon / star / diamond / cross : strokeLinejoin: "round"
divider / wave / corner / line / arrow     : strokeLinecap:  "round"

也就是说"尖角 / 圆角"、"平头 / 圆头 / 方头"这类纯视觉决策用户根本改不了 —— 属性栏里连控件都没有。 （顺带说明：svgAttrName() 里早就备好了 strokeLinecap → stroke-linecap 的映射， 但全仓库 0 处使用 —— 一个"准备了却没用"的能力。）

1.2 做法：值 → 默认值 的映射即能力清单（"支持哪些形状"与"默认值是多少"不可能各写一份）

新增在 editor/data/decorationShape.ts（几何唯一口径）：

DECOR_LINECAP_OPTIONS / DECOR_LINEJOIN_OPTIONS     // 面板 select 的唯一来源
DECOR_LINECAP_DEFAULTS / DECOR_LINEJOIN_DEFAULTS   // 形状 → 改动前硬编码的值（= 能力清单 + 默认值）
decorSupportsLineCap(kind) / decorSupportsLineJoin(kind)
decorLineCapOf(config, kind) / decorLineJoinOf(config, kind)   // 取值 + 非法值回退
decorStrokeDetailDefaults(kind)                    // 注册处写入 defaultConfig
能力判据（避免"面板有控件、画面不动"的假能力）
  • 端点样式只在「描边是开放路径，或每段虚线是独立子路径」的形状上可见 → line / arrow / divider / wave / corner / dashed-box（6 个）。
    闭合且实线的矩形 / 圆 / 椭圆改它画面纹丝不动 → 不给。
  • 转折样式只在「描边路径上存在真实拐角」的形状上可见 → triangle / polygon / star / diamond / cross / arrow / corner（7 个）。
    矩形 / 圆 / 椭圆没有拐角（圆角靠 borderRadius）、线条与虚线框没有拐角 → 不给。
  • 默认值必须等于改动前硬编码的那个值：dashed-box 此前没写 linecap（SVG 缺省 butt）， 所以它的默认值是 butt 而不是 round。默认态产物逐字不变

面板片段收在 editor/data/decorFields.ts#decorStrokeDetailFields(kind)，注册处按能力追加；渲染端（编辑区 DecorationSvg / 发布端 renderDecorSpec）读的是同一份图元，因此双端一致由构造保证。

1.3 形状组（shape）同步：同一套能力，按 shapeType 动态显隐

形状组与装饰组共用几何（shapeSpec() → 装饰组图元）。它多一档 「跟随形状默认」（值 = 空串）： 因为同一个 shape 组件可能被切成线条（默认圆头）或虚线框（默认平头）， 写死一个 defaultValue 必然对其中一种撒谎。空串走 decorLineCapOf 的形状默认分支。

2. 线型口径收口：「点划线」暴露 + 14 份字面量合成 1 份

挖出的真实缺陷（面板会骗人）：resolveDecorStroke() 自带一张虚线节奏表 （dashed→8 4 / dotted→2 4），与 decorBorderDash()（还支持 dash-dot→12 4 2 4）是同一映射的第二份实现。 圆环走后者、其余 7 个形状走前者。
后果：给 borderStyle 加「点划线」这一档时，只有圆环会动、其余 7 个形状静默变实线。
  • 修法：resolveDecorStroke 改调 decorBorderDash()，节奏只此一份。
  • decorLineDash() 补 dash-dot（此前线条族压根没有这一档）。
  • 新增 DECOR_BORDER_STYLE_OPTIONS（实线/虚线/点线/点划线/无边框）与 DECOR_LINE_STYLE_OPTIONS（实线/虚线/点线/点划线）， 把 14 份抄写副本（边框表 7 处 + 线条表 6 处 + 圆环内联 1 处）全部换成引用。
  • 圆环的 borderStyle 只驱动虚线节奏、不控制有无描边（环本身就是描边）→ 它用不含「无边框」的那张表， 否则就是一个"选了没反应"的假控件。

3. 圆环「外环粗细」：解锁一个已存在但面板不可达的能力

几何里本来就有 if (strokeWidth > 0) 再画一圈半透明细边（双环效果）， 但面板从未提供入口 → 这个能力一直不可达。补上 strokeWidth（默认 0 = 与历史产物逐字一致）。

4. 媒体组：音频（audio）接入动态数据 + 认证三态 + 媒体族外观口径收口

缺口：媒体组三件套里，图片与视频都能接接口动态资源，音频只认面板里填死的地址 —— 「数据模式 / 接口地址 / 认证开关 / 全局数据源绑定」整段缺失，也就是说"认证 / 非认证两种接入方式"在音频上根本不存在。

4.1 属性栏：与图片 / 视频完全同构

...dataSourceSchemaFieldsNoStatic     // 全局数据源 + 数据模式 + apiUrl/apiPath/apiMethod/apiDataPath
                                      // + apiHeaders/apiBody/apiInterval + authEnabled（三态）
apiSrcField   音频地址字段            // 留空依次尝试 url → src → audio → audioUrl → path
apiCoverField 封面地址字段            // 留空依次尝试 cover → poster → image → thumbnail
boxShadow / borderStyle / emptyBg / emptyColor          // 媒体族公共外观，补齐

接口模式下自动隐藏静态「音频源 / 封面」（不留两个打架的入口）；authEnabled 三态 （true 注入 / false 明确不注入 / null|undefined 跟随站点全局认证态）与全局数据源绑定 全部复用已有机制，不新增第二套取数实现。

4.2 样式口径：从"自带一份字面量"改为读 resolveMediaStyle

音频渲染器与 codegen 此前各自写 radius * 10、各自写默认色值 —— 正是"同批字面量写两处必然漂移"的隐患 （图片就曾因此差 10 倍）。现两端都只读 resolveMediaStyle()。
默认值刻意收窄为"改动前的观感"（空态透明底 + 副标题色文字），因此历史场景产物零回归： 

resolveMediaStyle(config, {
  radius: 4, bgColor: "rgba(255,255,255,0.06)", emptyText: "未设置音频",
  emptyBg: "transparent",           // 媒体族默认是 rgba(128,128,128,.10)，此处显式收窄
  emptyColor: "rgba(229,231,235,0.6)"  // 媒体族默认是 #999999，此处显式收窄
})
