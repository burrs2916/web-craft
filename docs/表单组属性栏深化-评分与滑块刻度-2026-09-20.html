2. 真实缺陷：评分在编辑区被双重缩放（只有真实浏览器能抓到）

现象：改造后编辑区 300×150 容器里，评分内层实测 223.5×40.4，而发布端是 170.7×29.8 —— 两端差 1.35 倍。

根因：旧编辑区渲染器把 factor 乘进每个 width/height/fontSize（不做 transform），发布端却是 transform。两套机制恰好等价，所以历史上没暴露。本轮把编辑区统一到 transform: scale(factor) 后，旧的「乘进尺寸」没删 → 1.35 × 1.35 双重缩放。

处置：编辑区星/文字一律写自然尺寸，缩放只由内层一次 transform 完成。修复后两端逐项相同（下表）。

教训：jsdom 不实现布局，单测永远抓不到这类几何分叉；必须走 --dump-dom 真值页 + 发布产物双端取证。

3. 数据感知族：认证接入升级为三态（与内容数据源同一口径）

骨架屏 / 加载动画 / 空态占位这三个组件不渲染数据、而是轮询探测一个接口来决定显隐，其认证字段是 bindAuthEnabled。改造前它是两态 toggle：

  • 缺省渲染成 OFF；而运行时把 undefined 当「不带 Token」。
  • 面板无法表达「跟随站点全局」这一最常用意图；站点全局开着时，面板说「不改」，行为却与站点配置无关 —— 正是本仓库记录在案的「面板骗人」形态。

处置：authEnabledField() 增加 key 形参（默认仍是 authEnabled），bindAuthEnabled 改为复用同一份 AUTH_ENABLED_OPTIONS 与 readAuthEnabled；三处 codegen（skeleton / spin / emptyState）与编辑区 useBindVisibility 全部改为三态原样透传（不再 === true）。

配置取值产物语义
未设置var authEnabled = null跟随站点全局（运行时读 window.__WC_AUTH_ENABLED）
true / "true"var authEnabled = true强制注入 Token
false / "false"var authEnabled = false公开接口，明确不带

兼容性：站点全局默认关闭时，历史场景（undefined）行为不变；显式 false 的场景也完全不变。只有「站点全局开启 + 从未设置过该字段」的场景会开始带 Token —— 这正是「跟随全局」的正确语义。
