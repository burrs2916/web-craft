2. 修复思路：不做「第二份 SVG 字符串版」

这 25 个组件的图形在编辑区由约 1900 行手写 React SVG 产出（DataVRenderer.tsx + datavScalable.tsx + 两个雕花框）。若按老办法「把几何再手抄一份字符串版」，必然产生第二份会漂移的字面量 —— 本仓库已经因为同类做法栽过两次（20 个装饰渲染器各写一遍几何、图标组的状态规则被 inline 压死）。

因此改成：发布端直接复用编辑区那一个 React 组件做静态渲染（react-dom/server 的 renderToStaticMarkup）。几何、配色、SVG 属性、SMIL 动画由构造保证逐字一致，不存在两端各写一份的可能。

唯一的差别是尺寸来源：编辑区靠 ResizeObserver 实测容器像素，静态渲染时没有浏览器测量。 解法是把尺寸收口成一个 Context：

// src/editor/renderers/datavRenderSize.ts（新增）
export const DatavRenderSizeContext = createContext<DatavRenderSize | null>(null);

// 容器尺寸的唯一取用口：发布端注入值优先，否则 ResizeObserver 实测
export function useDatavBoxSize(ref) {
  const override = useDatavRenderSize();
  const [size, setSize] = useState(DATAV_FALLBACK_SIZE);
  useEffect(() => { if (override) return; /* ResizeObserver 实测 */ }, [!!override]);
  return override ?? size;      // ← 同一段几何代码，只有尺寸输入不同
}

// src/codegen/components/datavDecor.ts（新增）
renderToStaticMarkup(createElement(DataVRenderer, {
  config, componentId: component.id, mode: "preview",
  sizeOverride: { width: 400, height: 300 },   // 来自 component.transform
  uidOverride: "datvc1",                       // 发布端 id 必须可确定
}));
顺带收益：动画是 SVG SMIL（<animate>）与 CSS keyframes，都是声明式的 —— 静态 HTML 里照常播放，不需要任何运行时脚本。<animate> 在产物里完整保留（浏览器实测已确认）。

三、顺带挖出并修掉的 3 个真实缺陷

缺陷 1 P1 装饰动画 / 线条特效「只有编辑区生效」

ANIMATION_SCHEMA（动画 12 种）与线条特效（14 种）此前只由编辑区的 DecorationWrapper 实现， 发布端 codegen/components/decoration.ts 没有任何对应逻辑 —— 面板上改了动画，编辑区在动， 正式站点一动不动。这是同一类「发布 ≠ 编辑」缺陷，只是没有空 div 那么显眼。

缺陷 2 P1 「线条粗细」在部分组件上是假控件

DATAV_STROKE_RULES 是一张手写的「选择器 → 基准线宽」表，用来给手写死线宽的 SVG 做 CSS 覆盖。 但这些 SVG 后来被重写过，选择器指向的元素已经不存在了 —— 整张表全部失效： 

// 表里写的（已失效）              // 组件实际产出的
"deco-7": polyline[stroke-width=4]  →  path（双翼装饰重写后已无 polyline）
"deco-8": polyline[stroke-width=2]  →  path / ellipse
"deco-9": circle[stroke-width=10]   →  path
"deco-12": path[stroke-width=2]     →  已由几何 * sw 内部驱动（不该出现在表里，否则平方级放大）

修法是让表从真实产物反推并加锁：只有「不随 strokeWidth 变化」的静态线宽字面量才进表。 同时把「面板要不要显示这条控件」也交给同一个判据函数：

// editor/data/datavDecor.ts
export function datavStrokeWidthSupported(kind, idx) {
  if (kind === "border") return Number(idx) >= 2;   // 边框 1 是纯填充多边形，一根描边都没有
  return Number(idx) !== 10;                  // 装饰 10 雕花边框是纯填充路径（参考 SVG 明确「无描边」）
}
契约测试当场抓到的：新增的「面板显示了这条控件，就必须能改变产物」用例， 第一次运行就报出 datav-decoration-10 是假控件 —— 雕花边框是纯填充路径，没有任何线宽可调。据判据把它从面板隐藏（而不是保留一个点了没反应的滑块）。

缺陷 3 P1 线条特效颜色解析把「0 通道」改成默认值

// 原实现：|| 兜底把合法的 0 也吃掉了
r: parseInt(hex.slice(1,3),16) || 33,     // "#00ff00" → 0 || 33 = 33
g: parseInt(hex.slice(3,5),16) || 150,
b: parseInt(hex.slice(5,7),16) || 243,    // → rgb(33,255,243)：绿色变青色

// 修法：只在格式非法时兜底
const v = parseInt(hex.slice(1,7), 16);
if (Number.isNaN(v)) return FALLBACK;
return { r:(v>>16)&0xff, g:(v>>8)&0xff, b:v&0xff };

影响面：#ff0000（纯红）会渲染成粉色、#0000ff 会渲染成青色。 因为编辑区与发布端一起错，所以一直没人发现 —— 这也正是「两端一致」不等于「两端正确」的典型例子。
