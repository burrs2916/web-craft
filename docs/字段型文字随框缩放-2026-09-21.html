二、本轮交付：7 个字段型组件的「文字随框缩放」

与 transform 缩放是两种机制，勿混。字段层铺满拖动框、边框环随框走——几何已自动「随框」， 缺的是排版密度：框放大后字号不动，4K 大屏「框大字小」（煤矿喷雾监控主视图即 3840×2160）。 开启后字号按「框 / 注册表 defaultSize」倍率缩放；不碰几何、默认关（零回归）。

设计要点

  • factor 编译期算出：字段型没有缩放骨架、没有运行时量测脚本。编辑区读 props width/height（画布已传 = transform 尺寸），发布端读 component.transform —— 同源、零运行时开销。
  • 唯一口径：editor/data/scaleFit.ts 新增 FIELD_FITS（7 组件 ref= 各自 defaultSize，夹 0.5~4）+ fieldScaleFactor(type, w, h, enabled)；关闭 / 未知类型 / 尺寸未传恒为 1。
  • 派生量自动跟随：factor 只乘进 fontSize / labelFontSize 两个变量，图标宽（fontSize×1.2）、行高、占位字号等派生量自动跟随。
  • 历史结论不冲突：当初「字段型刻意不给 scaleFit」针对的是 transform 骨架方案（会让边框环与字段层脱开）；本方案只乘字号，不碰几何。

覆盖范围

面板（fieldScaleFitField，布局组）：form-input / textarea / select / date / time / number / file 共 7 个；两端各 7 处接线（date/time 共用 DateTimeField / datetimeInputCodegen）。
