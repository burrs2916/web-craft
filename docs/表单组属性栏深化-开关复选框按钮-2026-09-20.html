一、开工复核：先修好"取证工具"本身

本轮开工第一件事是复核前七轮的结论。查 codegen/components/index.ts 注册表确认：表单 17 / 媒体 3 / 表格 5 / 图标 3 / 形状 / 装饰 45 全部有发布端实现，任务原文「从标签组件开始都没完成」确实是 P0 时期的状态。于是本轮做的是深度而不是补注册。

随后按第 7 轮留下的待办，要对 form-switch / form-checkbox / form-button 做编辑区侧真值取证（与已完成的发布端 headless 探针对照）。结果 src/__measure__ 真值页的 #out 始终停在 "boot"（长度 4），意味着 React 应用模块从未执行。

根因

用 --enable-logging=stderr 抓控制台，拿到唯一一条真实错误：

Uncaught ReferenceError: FormButtonRenderer is not defined
  source: http://127.0.0.1:8791/assets/measure-DqiMdTwM.js (256)

src/__measure__/main.tsx 用了 <FormButtonRenderer /> 但漏了 import——模块在求值阶段就抛异常，所以 #out 连 "module-ran" 都写不进去。此前把现象误判为"ES module 在 headless 下加载失败 / dump-dom 时序"，实际是一次普通的漏 import。教训：dump-dom 拿到空结果时，先看控制台，别先怀疑时序。

补上 import 后真值页立刻可用，从而拿到了编辑区侧的第一手读数。

二、form-switch（16 → 28 字段）与 form-checkbox（17 → 26 字段）

两者共用一份新口径 src/editor/data/toggleStyle.ts，把"开关/复选框的外观与排版"收成纯函数，编辑区渲染器与发布端 codegen 都只读它。

新增字段

form-switch 2.0.0 28 字段
  • 外观层：bgColor / borderColor / borderWidth / borderRadius（默认 0）/ paddingX / paddingY / opacity / fontWeight
  • 开关皮肤：trackOffColor（默认 #ffffff）/ trackOffOpacity（0.3）/ trackOnOpacity（0.5）/ thumbOffColor（#E0E0E0）
  • 原有：内容 / 校验 / 布局(scaleFit/align/vAlign) / 状态 / 样式
form-checkbox 2.0.0 26 字段
  • 外观层：与开关同一组（复用 toggleAppearanceSchemaFields）
  • 未选中色：uncheckedColor（缺省跟随 accentColor）
  • fontWeight 与未选中色此前只有编辑区认，发布端完全不认 → 已两端同源
关键约束 外观层（底色 / 内边距 / 圆角 / 不透明度 / 边框）必须挂在"缩放内层"才能随拖动框缩放。挂在最外层就成了"框变而底色不动"。本轮的 toggleShellCss() 只输出显式配置过的声明——默认返回空对象，因此零配置的产物与改动前逐字一致（零回归实测见第六节）。

三、form-button（19 → 22 字段）：修掉两个假控件

探针实测确认：改动前按钮恒 width/height:100% 铺满容器，面板上的 size（小/中/大）与 fullWidth（宽度撑满）改了产物毫无变化——典型假能力。

现在默认走「自然尺寸 + 居中 + 随拖动框等比缩放」骨架（与表单组其他成员同一套三层结构）：

  • size 兑现为盒高与左右内距：BUTTON_SIZE_BOX = small 32/12、medium 38/16、large 44/22
  • 自然宽由文本决定；缩放系数 BUTTON_FIT = refW 120 / refH 40，夹在 0.4~6
  • fullWidth=true 时退回铺满模式（此时它在面板上才真正有意义）
  • scaleFit=false 仍居中但系数恒 1，且不挂缩放脚本

发布端改由新的共享构造函数 buildButtonFitHTML() 产出，与编辑区实时渲染走同一份结构。

四、P1 真 bug舞台摆放两端分叉：画布靠左、发布居中

这是本轮挖到的真正打破"发布与预览效果相同"的缺陷，也是本轮最有价值的修复。

现象

第 4 轮已经把默认摆放收口成 STAGE_ALIGN_DEFAULT = "center"，并同步改了面板 defaultConfig。但收口只做了一半——只有发布端读了它：

// 编辑区 src/editor/renderers/FormSwitchRenderer.tsx:44
const align = String(config.align ?? "left");        // ← 回退值写死 left

// 发布端 src/codegen/components/form.ts:1249
align: String(c.align ?? STAGE_ALIGN_DEFAULT),       // ← center

于是配置里没有 align 键时（老场景保存的配置、或面板值被清空），画布靠左、发布端居中。真值页实测证据：

修复前 · 编辑区 cN：stage: justify=flex-start
修复前 · 发布端 cN：stage: justify=center        ← 同一份配置，两种观感

波及面审计（不猜，逐文件核实）

组件编辑区回退发布端回退判定
form-switch?? "left"?? STAGE_ALIGN_DEFAULT分叉
form-checkbox?? "left"?? STAGE_ALIGN_DEFAULT分叉
form-radio?? "left"?? STAGE_ALIGN_DEFAULT分叉

修复：把"回退"这一步也收成唯一口径

根因不是常量没定，而是"对 align 求值"这件事被写了两遍。所以在 editor/data/scaleFit.ts 增加唯一入口，两端都必须调它：

export function stageAlignOf(config: Record<string, unknown>): string {
  return String(config.align ?? STAGE_ALIGN_DEFAULT);
}
export function stageVAlignOf(config: Record<string, unknown>): string {
  return String(config.vAlign ?? STAGE_VALIGN_DEFAULT);
}

编辑区 5 个渲染器（switch / checkbox / radio / button / segmented）与发布端 2 处 codegen（form.ts 4 个组件点位 + segmented.ts）全部改调它。

顺带修掉第二个同类缺陷：切 scaleFit 开关内容会跳位

审计中还发现 codegen/shared/scaleSkeleton.ts 里有一层重复映射：

// 修复前：两条分支用两套映射，对未知值的处理不同
function toAlign(v){ return v==="right"?"right" : v==="left"?"left" : "center"; }  // 未知 → center
// 而唯一口径 alignToFlex() 是：未知 → flex-start

if (o.scaleFit) { ...align: toAlign(o.align)... }   // 走 toAlign
else            { ...scaleStageCss(o.align, ...) }  // 走 alignToFlex

同一个 align 值，scaleFit 开时居中、关时靠左——切一个开关内容就跳位。toAlign / toVAlign 已删除，两条分支统一把原始值交给 scaleStageCss（它对 undefined 用形参缺省取 STAGE_ALIGN_DEFAULT）；scaleFitStage 里硬编码的 ?? "center" 也一并去掉，避免第三处默认值。

五、authEnabled 三态：面板终于能表达第三态

这是横切基础设施缺口——第 7 轮记录为「"认证接入灵活全面"的最后一块」。三态语义：null 跟随站点全局 / true 强制注入 / false 明确不注入。

修复前：面板是 toggle，只有开/关两态，第三态在 UI 上表达不了；更糟的是 toggle 对 undefined 渲染成 OFF，而 codegen 把 undefined 当"跟随全局"——面板在骗人。临时对策是 defaultConfig 里显式落 authEnabled: false，治标不治本。

修复后：新增 editor/data/fieldSelect.ts（sameOptionValue / selectDisplayValue / resolveSelectValue / readTriState）与 editor/data/authMode.ts（AUTH_ENABLED_OPTIONS / authEnabledField() / readAuthEnabled()），把 authEnabled 从 toggle 换成三态 select，并统一全仓取值入口。

顺带修掉一个真实的两端相反缺陷：面板 select 写回字符串时把 false 变成 "false"，而 Boolean("false") 为真——同一份配置在编辑区与发布端行为相反。readTriState() 对 "false" 字符串做了特判。

同类问题也出现在 echart-pie 的玫瑰图开关上：config.roseType || false 让历史脏值 "false" 成真值，编辑区画玫瑰图、发布端画普通饼图。已改为白名单判据 roseType === "radius" || roseType === "axis" 两端口径一致。
