# 技术栈选型

> 本文档定义 WebCraft 各层的技术选型，明确哪些"钉死"、哪些"可选"。
> 所有开发决策应与本文档保持一致。
> 最后更新：2026-08-19

---

## 一、总原则

**钉死核心，开放扩展。**

- 平台核心能力（后端、运行时、AI 引擎）→ 钉死，保证体验一致和 AI 效果
- 用户可见的表现层（前端、内容、样式）→ 开放，给用户自由度
- 模型/服务提供商 → 不钉死，给用户选择权

---

## 三、云端站点运行时

> 钉死的是"默认方案"，保证 AI 运维助手精准工作。
> 高级用户可以通过 SSH 自行扩展，但平台不保证超出范围的运维支持。

### 3.1 Web 入口

| 层级 | 技术选型 | 是否钉死 | 理由 |
|------|----------|:--------:|------|
| **Web 服务器 / 反向代理** | **Nginx** | ✅ 钉死 | 行业标准、性能强、生态成熟、运维知识通用、AI 助手好做 |

### 3.2 站点后端服务

| 层级 | 技术选型 | 是否钉死 | 理由 |
|------|----------|:--------:|------|
| **站点后端** | **webcraft-server（Rust + Axum）** | ✅ 钉死 | 平台提供，用户不能改，保证安全和稳定 |
| **进程管理** | **systemd** | ✅ 钉死 | Linux 标配，不用 supervisor/pm2 |
| **服务管理方式** | systemctl --user + linger | ✅ 钉死 | 无需 root 权限也能自启动 |

### 3.3 数据库

| 层级 | 技术选型 | 是否钉死 | 理由 |
|------|----------|:--------:|------|
| **主数据库（默认）** | **MySQL 8.x** | ✅ 钉死 | 普及率最高、运维命令简单、AI 助手容易精准操作、用户熟悉度高 |
| **主数据库（备选）** | PostgreSQL 15+ | ✅ 支持 | 高级用户可选，平台提供安装和基础运维 |
| **缓存** | **Redis 7.x** | ✅ 钉死 | 行业标准，需要时安装 |

> **说明**：站点数据库必须是独立安装的专业数据库，不使用 SQLite。
> SQLite 只用于本地客户端的单用户场景。

### 3.4 SSL / 安全

| 层级 | 技术选型 | 是否钉死 | 理由 |
|------|----------|:--------:|------|
| **SSL 证书** | **Let's Encrypt + certbot** | ✅ 钉死 | 免费、标准、自动化 |
| **证书管理工具** | certbot | ✅ 钉死 | 最广泛使用 |

### 3.5 备份

| 层级 | 技术选型 | 是否钉死 | 理由 |
|------|----------|:--------:|------|
| **数据库备份** | mysqldump / pg_dump | ✅ 钉死 | 官方工具，可靠 |
| **文件备份** | tar.gz | ✅ 钉死 | 简单可靠，通用格式 |
| **备份存储** | 本地 + 可选远程 | ⚠️ 半开放 | 默认本地，高级用户可配置远程存储 |

### 3.6 远程连接

| 层级 | 技术选型 | 是否钉死 | 理由 |
|------|----------|:--------:|------|
| **远程管理协议** | **SSH + SFTP** | ✅ 钉死 | 标准协议，所有 Linux 服务器都支持 |
| **SSH 实现** | OpenSSH（服务端） | ✅ 钉死 | Linux 标配 |

## 四、AI Agent 引擎

| 层级 | 技术选型 | 是否钉死 | 理由 |
|------|----------|:--------:|------|
| **引擎语言** | Rust | ✅ 钉死 | 跟客户端一体，性能好 |
| **Agent 协议** | OpenAI Function Calling 格式 | ✅ 钉死 | 行业事实标准，兼容所有主流模型 |
| **工具协议** | 自研 `AgentTool` trait | ✅ 钉死 | 统一接口，插件和内置工具共用 |
| **上下文管理** | 压缩 + 截断 双层策略 | ✅ 钉死 | 已实现，效果验证 |
| **权限模式** | Auto / Confirm 两级 | ✅ 钉死 | 简单够用 |
| **模型提供商** | 多模型支持，用户自选 | ❌ 不钉死 | 用户根据需求和成本选择 |
| **模型版本** | 用户可切换 | ❌ 不钉死 | 跟随模型迭代 |

## 六、不钉死的（用户自由选择）

| 领域 | 说明 |
|------|------|
| 前端框架 | 任何能产出静态文件的方案（React/Vue/Svelte/原生等） |
| CSS 方案 | Tailwind / 原生 CSS / CSS-in-JS / Sass，用户自选 |
| 静态站点生成器 | 平台内置 SSG / Hugo / VitePress / Next.js 静态导出 等 |
| JavaScript 库 | 用户自由选择 |
| 第三方前端服务 | 统计、评论、搜索、客服等，用户自行接入 |
| 第三方后端服务 | 邮件、CDN、对象存储等，通过插件接入 |
| Linux 发行版 | Debian/Ubuntu/CentOS 等主流发行版都支持 |

## 七、技术决策原则

当遇到技术选型决策时，按以下优先级判断：

1. **AI 体验优先**——能让 AI 助手更精准的方案优先
2. **行业标准优先**——主流方案优先，降低用户学习成本
3. **运维可靠优先**——生产环境稳定比花哨重要
4. **简单够用优先**——不追求技术纯度，够用就好
5. **用户自由优先**——不影响前四条时，给用户更多选择

## 八、版本策略

- **钉死的技术**：大版本跟随 LTS 版本升级，不追新
  - MySQL：8.x LTS
  - Nginx：稳定版
  - Redis：7.x
  - Rust：stable 通道
- **开放的技术**：用户自行决定升级节奏
- **客户端依赖**：定期升级，保持在主流版本区间
