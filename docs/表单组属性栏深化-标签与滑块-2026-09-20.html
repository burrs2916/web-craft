关键设计取舍

  • 外观层必须挂在"缩放内层"：只有被 transform: scale() 缩放的那一层，底色与内边距才会跟着拖动框一起等比放大缩小。 挂到外层就会出现「框变大、标签底色纹丝不动」。声明统一由 labelInnerCss(s) 给出（圆角走表单族 ×SHAPE_RADIUS 口径）。
  • 文字节点单独包一层 span：接口数据到达时只替换它的 textContent —— 不会连带抹掉后缀与必填星号， 且 textContent 赋值天然免疫注入。静态模式与接口模式的结构完全一致。
  • 拿走整组数据配置的诱因：不给纯文字组件注入通用数据源分组（dataConfigMixin 显式声明制）， 但这里提供的是真实生效的接口取字能力，并已用「面板控件必须能改变产物」的锁逐字段验证。

3.2 P1 缺陷：发布端拖动滑块时画面完全不动

现象：发布页里拖动滑块，填充条、滑块、数值回显全都不动（原生 range 的 value 本身在变，所以表单提交值是对的，看起来"能用"）。

根因：产物把 JSON.stringify(suffix) 直接拼进了双引号属性 oninput="…"。 JSON.stringify("%") 产出的是带裸双引号的 "%"， 属性在第一个 " 处提前闭合 → 处理器被截断成 var txt=this.value+（语法错误，整个 handler 失效）， 余下内容被解析器吞成垃圾属性。默认配置（suffix:""）同样中招：this.value+""。

// 修复前（真实浏览器 allAttrs）
"attrs": "type,id,min,max,step,value,style,oninput,%\";var,lb"   ← 两个垃圾属性
"oninput": "var t=…;var txt=this.value+"                          ← 被截断，语法错误
"afterInput": ""                                                  ← 数值回显没更新

// 修复后
"attrs": "type,id,name,min,max,step,value,style,oninput"          ← 干净
拖到 80 → trackW=80%  thumbLeft=calc(80% - 8px)  bubbleLeft=80%  bubbleText=80%  labelText=80%
拖到  3 → trackW=3%   thumbLeft=calc(3% - 8px)   bubbleLeft=3%   bubbleText=3%   labelText=3%
bubbleVsThumbCenter = 0                                           ← 气泡与滑块中心对齐

修复：escapeAttr(JSON.stringify(suffix))，并加回归锁覆盖 % " ' <b> a"b 五种后缀。 同类排查命令：grep -n 'oninput="\|onchange="\|onclick="' src/codegen/components/*.ts | grep JSON.stringify（全仓库仅此一处）。

四、顺带发现的两处"面板骗人"问题

1 · 认证开关的默认值

共享片段 apiFields() 里的 authEnabled 是 toggle：undefined 在面板上渲染成 OFF， 而 codegen 把 undefined 解释为「跟随站点全局认证态」。站点全局开着认证时，用户看到"关闭"、请求却带着 Token。

本轮对策：form-label 显式落 authEnabled:false（与图片/视频/音频同做法），让面板与行为一致。

2 · 第三态在 UI 上无法表达

数据模型是 true 注入 / false 明确不注入 / null|undefined 跟随全局， 但 toggle 只能表达两态。要真正"灵活全面"需要面板 select 支持 optionValues（字符串↔真值映射）—— 涉及 1 处共享片段 + 5 处内联 toggle + 约 10 个 normalize 点，建议单独一轮做，本轮未动。
