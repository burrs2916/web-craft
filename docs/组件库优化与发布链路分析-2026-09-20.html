一、依赖链核实结论：预览 / 发布如何把代码写进「我的网站」绑定目录

先给出经过源码核实的完整链路，这是后续所有一致性工作的判据基础——编辑器属性栏写入的 config 是唯一源头，预览与发布是两个消费端，二者必须共用同一份取值口径才能保证「编辑模型 == 预览 == 发布」。

1.2 绑定关系：唯一真相链（双向同步）

目录绑定scene.metadata.localWorkDir  ⇄  site.local_workdir
站点绑定scene.metadata.boundSiteId  →  站点记录

两条同步方向都落在 src/store/sceneStore.ts：

  • 绑定站点时（sceneStore.ts:453–476）：把场景的 localWorkDir 推给站点 —— 场景是源头。
  • 设置目录时（sceneStore.ts:492–514）：把 localWorkDir 反向同步到已绑定站点，日志 "Site local_workdir synced"。

因此无论从哪一端改目录，{localWorkDir}/{framework}/ 始终是同一个物理路径。

一句话结论：「我的网站中绑定的目录」就是 {localWorkDir}/{framework}/。预览与发布写的是同一个目录，差别仅在于预览额外产出合并版 preview.html。所以两端视觉一致的唯一保障，就是让编辑区渲染器与发布端 codegen 读同一份取值口径纯函数——这正是本轮全部工作的主线。

2.3 修复的真实缺陷（非顺手重构，均有证据）

P1authEnabled 被压成布尔

编辑区 useApiDataFetch 用三态（null=跟随全局 / true=强制带 token / false=强制不带），而级联 codegen 写成 === true，导致「跟随全局」被误判为「不带 token」。
证据：契约测试断言失败 → 打印产物确认 → 已改三态透传（codegen/components/cascader.ts），并 grep 确认其余 codegen 本就是三态口径。

P1评分：编辑区缩放、发布端固定

编辑区 rate 随框缩放，发布端却按固定尺寸渲染 —— 拖大设计盒后两端视觉分叉。已抽 scaleFit 两端同源。
证据：两端产物尺寸对照探针。

P1图片圆角双端口径差 10 倍

编辑区 sx 数字圆角走主题 shape.borderRadius=10（×10），发布端按字面 px 输出。面板填 3 时，编辑区 30px、发布端 3px。已由 mediaStyle 统一。
证据：headless 量取编辑区圆角 30px vs 发布端 3px。

2.4 居中显示 + 随拖动框缩放

用户要求「组件在拖动框中居中显示，可随拖动框拖动放大缩小」。统一为 scaleFit 口径：内容按自然尺寸在铺满设计盒的 stage 中整体等比缩放并居中，编辑区（editor/data/scaleFit.ts）与发布端（codegen/scaleFit.ts）同源，率组件与后续组件共用。

  • 双模式取数：静态（面板条目 / JSON / 逐行文本自动迁移）与接口（apiUrl/apiPath）统一由共享解析器归一。

  • 取数运行时统一走 dataLoaderScript，带 token 时注入 Authorization 头。

复用要点（避免重蹈覆辙）
  1. 新增 / 改造组件一律走四件套：唯一取值口径解析器 + 共享字段外壳 + 类规则承载状态 + 隐藏 input 参与提交。
  2. 状态切换的属性（display/background/left/opacity…）绝不能写 inline —— inline 恒胜过非 !important 的样式表规则，会把状态规则永久压死。
  3. 三重验证缺一不可：codegen 契约测试 + 共享解析器单测 + 真实浏览器 DOM 探针。
