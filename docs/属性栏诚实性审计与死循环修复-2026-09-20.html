一、方法：可执行的诚实性审计

本轮不再逐组件人眼排查，而是写了一个可执行的扫描器（现已成为永久回归锁 src/codegen/__test__/panel-honesty-scan.test.ts）：对六组（表单/媒体/表格/图标/装饰/形状）共 142 个组件的每个标量面板字段，换一组对照值渲染两次 codegen，比对全量产物 （html + pageStyles + pageScripts）。改了面板值而产物逐字不变的，就是「假控件」—— 面板承诺了却改不动画面的字段。

开发探针阶段先后踩掉 4 个扫描器自身的大坑，全部记录在案（见第五节）—— 这些坑不排掉，审计结论全是噪音：第一次跑出「415 项假控件」，真实数字是 0。

二、P1 修复：两处发布端死循环（面板可触发的挂死）

P1decoration-grid / dots-pattern：spacing=0 死循环
面板把「间距」声明为 min: 0，而几何实现是 for (let x = spacing; x < 100; x += spacing) —— 用户填 0， x += 0 无限推进，发布端渲染直接堆栈耗尽挂死（实测 12GB 堆都撑不住）。 修复：editor/data/decorationShape.ts 两处步长加 Math.max(spacing, 1) 护栏。 取证：spacing=0 现正常产出 29KB 产物。

四、条件激活字段：hidden 条件或诚实文案（8 项）

这些字段条件成立后真实生效，不摘除，改为让面板如实反映生效条件：

  • labelGap ×8（input/textarea/select/date/time/number/cascader/file）→ hidden: labelPlacement !== "top"（内置悬浮模式的标签是绝对定位，间距不参与）。
  • form-rate.fontSize → hidden until showText（分值文案关闭时无文字可调）。
  • decoration-arrow.arrowCount → hidden until arrowType==="chain"（单/双向恒 1 个箭头）。
  • decoration-gradient.speed → hidden until animated（无动画则无速度）。
  • icon-button.borderWidth → hidden until variant==="outline"（实心/文字形态无边框）。
  • form-container.showHeader / columns → help 文案诚实化（标题区需标题/副标题；列数只是空态占位示意，发布端自由画布定位）。

五、方法论沉淀：扫描器本身的 4 个坑

#坑教训
1组件级 codegen 返回 string，且会向 ctx.pageStyles/pageScripts 追加内容（datav 边框 strokeWidth 就在 pageStyles）必须每次渲染用全新 ctx、比对全量产物，只看 HTML 会漏一整族
2codegen uid 用 Math.random，两次渲染序列位置不同 → uid 必然漂移每次渲染前重置随机序列起点
3布尔候选被 String 化成 "false" 后，c.showSubmit !== false 严格比较恒真 → 候选失效，一次性制造 400+ 误报候选值必须保留原始类型
4defaultConfig 常缺键（undefined），有效默认值来自解析函数兜底（?? "none"、num(c.opacity,1)）单候选对照值容易恰好命中有效默认值 → 每字段试 min/max 等多候选
