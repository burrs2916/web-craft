## 1. 产品概述

### 1.1 一句话定位

**本地运行的个人网站工作站 —— 内容创作、服务器管理、一键部署，三位一体的桌面 CMS。**

### 1.2 产品本质

WebCraft 是一个**本地 CMS + 远程服务器管理平台**：

- 软件本身**本地运行**（Tauri 桌面应用，Rust 后端 + React 前端，不是 Web 服务，不是 SaaS）
- 用户的内容、数据、配置全部保存在本地，**数据自主可控**
- 通过内置终端（SSH/SFTP）**连接并管理远程服务器**
- 核心价值：**内容创作 + 远程管理一体化，终端是连接本地和远程服务器的桥梁**

### 1.3 不是什么

- 不是又一款终端模拟器（Windows Terminal 已存在）
- 不是又一个 WordPress 替代品（不是远程 Web 管理）
- 不是云服务（内容不上传到我们的服务器）

### 1.4 竞争定位

| 竞品类型 | 代表 | 它们的弱点 | 我们的差异 |
|---------|------|-----------|-----------|
| CMS | WordPress | 远程 Web 管理，慢，攻击面大 | 本地运行，通过 SSH 管理 |
| 静态站点生成器 | Hugo/Hexo | 需要命令行基础，部署工具链复杂 | 可视化编辑 + 内置终端一键部署 |
| 终端 | Windows Terminal | 只是终端 | 内置 CMS + 部署工作流 |
| 编辑器插件 | VS Code | 通用工具，非 CMS | 专为个人网站设计 |
| 笔记 | Notion | 不面向网站发布 | 面向发布的内容管理 |

### 1.5 发布渠道与平台

- **首发渠道：微软商城（Microsoft Store）**，作为商业产品售卖
- 平台：Windows（首发）、macOS、Linux（后续）
- 商业模式见第 8 节

## 2. 目标用户

| 用户画像 | 核心诉求 |
|---------|---------|
| 有 VPS/服务器的开发者 | 本地写作 + 一键部署，不想手动 rsync |
| 想搭个人博客的技术爱好者 | 不想学命令行部署，但想拥有自己的服务器网站 |
| 追求数据自主可控的用户 | 拒绝 SaaS 锁定，内容必须在自己手里 |
| 多服务器运维人员 | 一个客户端同时管理多台服务器的多个站点 |

## 3. 系统架构

```
┌──────────────────────────────────────────────────┐
│           WebCraft 个人网站工作站（本地）           │
├──────────────────────────────────────────────────┤
│                                                  │
│  ┌─────────┐  ┌──────────┐  ┌────────────────┐ │
│  │ 内容创作  │  │ 远程连接   │  │ 部署与运维      │ │
│  │ (编辑器)  │  │ (终端/SSH) │  │ (一键部署)      │ │
│  └────┬────┘  └────┬─────┘  └───────┬────────┘ │
│       └────────────┴────────────────┘           │
│                      │                           │
│               ┌──────┴──────┐                    │
│               │  远程服务器   │  VPS / 云主机      │
│               └─────────────┘                    │
└──────────────────────────────────────────────────┘
```

技术栈（沿用现有）：

- 桌面框架：Tauri v2（保持桌面应用形态，不改 Web 服务）
- 后端：Rust + SQLite（rusqlite）+ Tokio
- 前端：React 18 + TypeScript + MUI + Zustand
- 编辑器：TipTap 3（富文本，已有 Markdown/表格/LaTeX/代码高亮扩展）
- 终端：xterm.js + portable-pty
- 传输：SSH/SFTP（现有自研实现）

## 4. 功能需求

### 4.1 站点管理（新增，CMS 的骨架）

多站点是 Pro 版的核心卖点，站点是内容、部署、服务器的组织单元。

**功能点：**

- FR-S1 站点创建向导：站点名称、域名、本地工作目录、目标服务器（从已有 SSH 连接选择）、部署方式
- FR-S2 站点列表：展示每个站点的状态（本地草稿数 / 已发布版本 / 最近部署时间 / 服务器连通性）
- FR-S3 站点配置：基本信息、部署目标、构建配置、主题设置，集中于一个配置页
- FR-S4 站点级数据隔离：每个站点独立的内容、媒体、部署历史
- FR-S5 站点健康检查：一键检测远程目录可写、磁盘空间、服务状态

### 4.2 内容创作（基于现有 Notebook 演进）

现有笔记本（分组/分类/标签/TipTap 富文本/搜索）是内容创作的底座，需演进为面向"发布"的内容模型。

**功能点：**

- FR-C1 内容类型：文章（Post）与独立页面（Page，如"关于我"）
- FR-C2 发布元数据：slug（URL 路径）、摘要、封面图、发布状态（草稿/已发布/定时）、发布时间
- FR-C3 SEO 字段：自定义 title、description、OG 图
- FR-C4 内容与站点关联：每篇内容归属于某个站点，支持跨站点复制
- FR-C5 Front Matter 视图：富文本与 Markdown（带 front matter）双视图切换
- FR-C6 定时发布：本地到点触发构建 + 部署；应用未运行时不触发、不补发（UI 明示"需应用运行"，并提供一键复制的服务器 cron 配置引导，见决策记录 #4）
- FR-C7 内容版本历史：保留每次发布的快照，可回滚
- FR-C8 草稿箱与回收站：删除内容进回收站，可恢复

### 4.3 主题与模板（新增）

**功能点：**

- FR-T1 内置主题库：首发 3~5 套开箱即用的主题（博客型、文档型、作品集型）
- FR-T2 主题配置：站点标题、Logo、导航菜单、配色、页脚，可视化配置
- FR-T3 自定义页面模板：关于页、归档页、标签页
- FR-T4 主题预览：发布前在本地预览真实渲染效果（内置预览服务器）
- （V2）FR-T5 主题市场 / 用户自定义主题开发

### 4.4 站点构建（新增，SSG 引擎）

个人网站首选静态生成：安全（远程只有静态文件）、快、免运维数据库。

**功能点：**

- FR-B1 静态站点生成器（Rust 实现）：内容 + 主题 → HTML/CSS/JS 产物
- FR-B2 本地预览服务器：浏览器或内置 WebView 预览整站
- FR-B3 增量构建：只重建变化的内容，秒级重建
- FR-B4 输出标准产物：目录结构兼容 Nginx/Apache 静态托管
- FR-B5 生成 sitemap.xml、robots.txt、RSS/Atom
- FR-B6 分类页/标签页/归档页/分页 自动生成

### 4.5 部署与发布（增强现有 SFTP）

现有 SFTP 已有：上传下载、递归目录、队列、断点、符号链接、批量、取消。需在其上构建"部署工作流"。

**功能点：**

- FR-D1 一键部署：构建 → 差异对比 → 上传变更 → 远程验证，一条流水线
- FR-D2 部署前预览：显示本地与远程的差异清单（新增/修改/删除），用户确认后执行
- FR-D3 部署目标：服务器目录（SFTP，首选）、对象存储（S3 兼容，V2）、GitHub Pages（Git，V2）
- FR-D4 远程 Web 服务器管理：检测/安装 Nginx 配置、重启服务、查看访问与错误日志（走内置终端）
- FR-D5 SSL 证书：集成 Let's Encrypt certbot 流程引导（走内置终端 + 引导式步骤）
- FR-D6 部署历史与回滚：每次部署存清单，一键回滚到任意历史版本
- FR-D7 多环境：同一站点支持 测试/生产 两个目标，先测试后生产
- FR-D8 部署通知：成功/失败系统通知，失败时定位到具体文件/命令

### 4.6 终端增强（增强现有终端）

终端是核心差异点，保持并增强。

**功能点：**

- FR-E1 SSH 连接分组与标签：多服务器分组管理，站点与连接关联（现有连接列表增强）
- FR-E2 命令建议：输入时基于历史命令与片段给出建议（现有 history/snippets 数据已有）
- FR-E3 输出过滤与关键词高亮：error/warn 自动高亮，按关键词过滤回滚输出
- FR-E4 会话保存与快速恢复：命名会话、重启应用后恢复
- FR-E5 常用运维动作一键化：查看日志/重启服务/磁盘空间/进程，预置命令面板（基于现有插件系统）
- FR-E6 多终端同时操作：一条命令广播到多个会话（V2）

### 4.7 Git 集成（新增）

**功能点：**

- FR-G1 站点内容 Git 版本化：本地仓库自动 commit 内容变更
- FR-G2 推送到远程仓库（GitHub/Gitee），作为内容备份
- FR-G3 部署历史与 Git 提交关联展示
- （V2）FR-G4 服务器端 Git 拉取部署模式（Pull 型部署）

### 4.8 媒体库（新增）

**功能点：**

- FR-M1 站点媒体库：图片/附件上传、列表、搜索、按内容引用
- FR-M2 图片处理：压缩、格式转换（WebP）、生成缩略图（Rust 实现）
- FR-M3 编辑器内粘贴图片自动入媒体库并生成相对引用
- FR-M4 部署时媒体随站点同步

### 4.9 数据库管理（扩展方向，V2）

- FR-X1 SSH 隧道连接远程 MySQL/PostgreSQL
- FR-X2 SQL 查询执行与结果表格展示
- FR-X3 数据库备份（dump 下载到本地）

### 4.10 商业化与许可（复用现有 licensing）

现有许可系统已支持试用/Pro/微软商城 IAP，直接复用。

**功能门控（Feature Gate）：**

| 功能 | 免费版 | Pro 版 |
|------|--------|--------|
| 站点数量 | 1 个 | 无限 |
| 内容创作 | 完整 | 完整 |
| 内置主题 | 基础 1~2 套 | 全部 + 高级主题 |
| 一键部署 | 手动 SFTP 上传 | 完整流水线 + 差异预览 + 回滚 |
| 部署目标 | 1 个/站点 | 多环境（测试/生产） |
| Git 备份 | - | 含 |
| 定时发布 | - | 含 |
| 媒体库图片处理 | 基础上传 | 压缩/WebP/缩略图 |
| 终端增强 | 基础 | 命令建议/过滤/一键运维 |
| AI 助手 | 有限次数 | 完整 |

## 5. 现有实现对照（差距分析）

> 基于对 biosphere-terminal-app 现有代码的盘点。

### 5.1 可直接复用（已有，质量好）

| 能力 | 现有实现 | 复用方式 |
|------|---------|---------|
| SSH 连接管理 | connection 模块（保存/测试/AES-GCM 加密密码） | 直接复用，增加分组 |
| 终端仿真 | xterm.js + portable-pty + 会话/分屏 | 直接复用 |
| SFTP 传输 | 递归/队列/断点/符号链接/批量/取消 | 作为部署流水线的传输层 |
| 富文本编辑 | TipTap（Markdown/表格/LaTeX/代码/任务列表） | 内容编辑器底座 |
| 笔记组织 | 分组/分类/标签/搜索/置顶 | 演进为内容模型 |
| AI 助手 | 多 Provider/端点/模型/工具调用/权限系统 | 增强为"建站助手" |
| 远程桌面 | VNC over SSH | 保留，作为增值功能 |
| 插件系统 | shell/http/脚本执行器 + 安全验证 | 承载一键运维动作 |
| 许可系统 | 试用/Pro/MS Store IAP/Feature Gate | 直接复用 |
| i18n | 中/英 8 命名空间 | 新增 CMS 命名空间 |
| SQLite 存储 | 迁移/仓库模式（repo） | 新增 CMS 表 |

### 5.2 部分具备（需增强）

| 需求 | 现状 | 差距 |
|------|------|------|
| 多服务器管理 | 连接平铺列表 | 缺分组/标签/站点关联 |
| 命令建议 | 有历史与片段数据 | 缺输入时智能建议 UI |
| 输出高亮/过滤 | 无 | 缺 xterm 输出后处理 |
| 会话恢复 | 应用内会话管理 | 缺跨重启持久化恢复 |
| 媒体上传 | 图标上传（icon_service） | 缺通用媒体库/图片处理 |
| 内容元数据 | 笔记有分类标签 | 缺 slug/状态/发布时间/SEO |
| 图标系统 | 分组图标/自定义上传 | 可复用于 UI，非业务 |

### 5.3 完全缺失（需新建）

| 模块 | 说明 | 工作量预估 |
|------|------|-----------|
| 站点管理 | 站点 CRUD、配置、健康检查 | 中 |
| 内容模型（Post/Page） | 发布元数据、状态机、定时 | 中 |
| SSG 构建引擎 | Rust 模板渲染 + 增量构建 + RSS/sitemap | **大（核心）** |
| 主题系统 | 模板语言 + 内置主题 + 配置 | **大（核心）** |
| 本地预览服务器 | 内置 HTTP 服务 | 小 |
| 部署流水线 | 差异对比 + 编排 + 回滚 | 中 |
| 部署历史 | 版本清单存储 | 小 |
| Git 集成 | libgit2 或 CLI 封装 | 中 |
| 媒体库 + 图片处理 | 图片压缩/WebP（Rust image crate） | 中 |
| SSL/运维引导 | certbot/Nginx 引导流程 | 中 |

**验收标准：** 两个站点内容/媒体/部署历史完全隔离；变更 1 篇文章后差异部署仅上传该篇相关文件（而非整站）；免费版创建第 2 个站点被 Feature Gate 拦截并引导升级；回滚到任意历史部署后线上内容与该版本清单一致。

### M3 — 上架微软商城

**验收标准：** 站点内容变更自动 commit 并可在 GitHub 远程仓库看到；定时任务在应用重启后按策略补跑；通过 SSL 引导完成一次真实 certbot 续期；staging 环境先行部署验证后一键提升到生产。

## 7. 非功能需求

- **性能**：万级内容下增量构建 < 2s；部署差异计算 < 5s
- **安全**：SSH 密码/密钥本地 AES-GCM 加密（已有）；CSP 沿用；不收集用户数据
- **离线**：除 AI 助手外全部功能离线可用
- **国际化**：中/英双语（沿用 i18next，新增 cms 命名空间）
- **可靠性**：构建/部署失败必须可定位（沿用 debug.log 诊断体系）
- **跨平台**：Windows 优先（商城首发），macOS/Linux 保持可编译

## 9. 决策记录（原待确认问题，2026-08-16 拍板）

| # | 问题 | 决策 | 理由与影响 |
|---|------|------|-----------|
| 1 | 内容渲染路线 | **纯静态 SSG**，不做动态站点管理 | 远程只有静态文件 = 攻击面最小、免运维数据库、性能最优；WordPress 式远程管理偏离"数据自主"定位。SSG 引擎方案见 [ssg-engine-design.md](./ssg-engine-design.md) |
